# パターンによる証明のわかりやすさと記述量

## 数学的な構造と推論を読み取れること

設計の第一の評価軸は、**どの構造を選び、その関係を使ってどの結論へ進むかを、
証明の記述から読み取れること**である。記述量の短縮も測定するが、行数が減ることを
わかりやすさの改善の条件にはしない。定義・補助証明・主証明の量は、その改善を提供する
費用として併せて記録する。

[Ramsey の完全な例](pwl-ramsey.md) を、この評価の基準とする。
辺の彩色を対象とし、`$x` は頂点や色を束縛し、`#x` は先に束縛した値との一致を要求する。
`(p,q) → c` は、異なる頂点 p,q を結ぶ辺が色 c であるという関係を表す。
次のパターンは、固定した v からの同色3辺を示す。

```text
(#v, $x) → $c :: (#v, $y) → #c :: (#v, $z) → #c :: _
```

読者は、v が共通の端点、x,y,z がその先の頂点、c が共通の色であることを、この一つの形から
読み取れる。鳩の巣原理の補題はその配置が存在することを示し、証明では同じ配置を取り出す。
次に x,y,z の内部に色 c の辺がある場合と、3辺がすべて反対色の場合を扱う。
各腕で選んだ頂点を使い、主張に書いた次の三角形へ進む。

```text
($x, $y) → $c :: (#y, $z) → #c :: (#z, #x) → #c :: _
```

辺のつながりと同色の条件が並んで現れ、証明の「同色3辺を選ぶ → 内部辺を調べる →
単色三角形を作る」という構成を追える。これがこの例で重視するわかりやすさである。
頂点の相異性、色の等式、場合分けの網羅性の証明は、完全なコードに含める。

## わかりやすさにつながる条件

1. **数学的な対象の形を表せる。** 三角形、同じ端点を持つ辺、同じ値が現れる2位置、
   前後の列と消す区間など、推論に使う配置がパターンとして見える。
2. **複数の値の関係を同じ記述に置ける。** 共通の頂点や色、逆元、写像の像、位置の順序を、
   対応する構成要素のところで読める。複数の前提をつなぐ共通の変数や頂点も扱える。
   入れ子の探索は必須ではない。
3. **場合分けが数学的な理由に対応する。** 各腕を読むと、どの配置がある場合を扱い、
   その場合に何を示すかがわかる。
4. **主張・分解・結論の構成を追える。** 補題が保証する配置を証明で取り出し、
   同じ名前の構成要素を使って結論や小さい対象を作れる。
5. **分解に付随する証拠と数学的な推論を整理できる。** 所属や等式の証拠を標準の規則で
   引き継ぎ、読者が配置を理解するためにライブラリの内部表現を調べ続けずに済む。
   各腕を正当化する証拠と補助補題は、検査できる形で示す。

| 例 | 見える構造 | 追うべき推論 |
|---|---|---|
| Ramsey | 同色3辺と、その先の三角形 | 内部辺の色に応じて単色三角形を作る |
| Schur | x、y、x+y に共通する色 | 加法の関係を持つ同色の三つ組を作る |
| Pumping | 走行列の同じ状態が現れる2位置 | その間の区間を反復する |
| 群の語 | 隣接する逆元対と前後の列 | 積を保ってその対を消す |
| 局所合流性 | 二つの消去箇所の一致・重なり・分離 | 位置関係ごとに共通の消去先を作る |
| 解消規則 | 同じ変数の正・負のリテラルを持つ二つの節 | 真偽の場合分けから残りを合わせた節を導く |
| 閉じた歩道の挿入 | 元の歩道の途中と閉じた歩道の両端の共有頂点 | 同じ頂点で接続し、新しい歩道を作る |
| 行列式の積の公式 | 中間添字を選ぶ写像の、同じ像を持つ2入力 | その2位置の交換で符号が反対の項を打ち消す |

この条件は、証明のどの段階にも適用できる。結論が存在命題か、等式か、帰納的な構成かで
限定しない。比較では、読者が対象の形・値の関係・場合分けの理由・結論の作り方を
どこから読み取れるかを具体的に示す。行数や補助述語の数は、この観察に添える比較項目とする。

[構造と推論が見える証明の例](pwl-readable-proofs.md) に、解消規則と閉じた歩道の挿入の
完全な両版を置く。解消は有限導出の正しさと空の節による充足不可能性まで、
挿入は任意の辺の関係での歩道の構成、始点・終点の保存、長さの関係まで Lean で検査する。
行列式の積の公式も、同じ像を持つ2入力の選択から、項の打ち消しと和の整理まで検査する。
Cauchy–Binet の公式、Lindström–Gessel–Viennot の補題、オイラー閉路の存在定理への展開も考察する。
選んだ部分の交換で対合を作る場合には、2回の構成で元に戻ることを証明する。
道の交点を使う例では、交換後も同じ交点と道が選ばれる条件をパターンの証拠に含め、選択の保存を示す。

## 短縮する操作

有望なのは、**複数の選択・分解で得たすべての結果に、同じ数学的な推論を適用するパターン**である。
選択した値だけを返すと、証明では、値を列挙結果から取り出し、元の対象のどこから来たかを
調べ直す必要がある。分解の等式や条件の証明を結果と一緒に保持すれば、その操作を共通化できる。
再帰する場合には、残りについて証明した性質も結果の型に保持し、次の段階へ渡せる。

この方向は、[type-pm-paper の序論](../../type-pm-paper/type-pm-paper.tex) の
「複数の分解を探索し、先に選んだ値を後の位置で参照する」という使い方と、
[pmo-paper3](../../pmo-paper3/main.tex) の多重集合の選択と SAT の例を参考にする。
後者は、探索による選択をパターンへまとめ、問題を小さくする再帰は残すという構成である。
証明でも、分解結果を列挙する仕組みの正しさを共通化し、各結果についての数学的な推論と
帰納仮定の適用を腕に残す。この証明への対応は、本設計で検討するものである。

**パターンを書けば任意の証明が短くなる、という条件ではない。**
同じ補題や自動化を使う Lean でも、同じ操作を共通化できる。
記述量について評価するのは、利用者が繰り返し書く必要のある証拠の取り出し・対応付けを、
パターンの組合せからどれだけ自動構成できるかである。

## 完全な例：離れた逆元対を消す

群 G の要素の有限列 w から、重ならない2箇所の逆元対を選んで消す。
群には結合的な積、単位元、逆元があり、積の交換律は要求しない。
候補を実行して列挙するため、G の要素の等式を判定できると仮定する。
G 自体の有限性は要求しない。

```text
$pre ++ $g :: #(g⁻¹) :: $mid ++ $k :: #(k⁻¹) :: $post
```

腕は次の等式の証拠を受け取り、r = pre ++ (mid ++ post) を返す。

```text
w = pre ++ g :: g⁻¹ :: (mid ++ k :: k⁻¹ :: post)
```

証明する性質は、パターンを含まない通常の命題である。

```lean
def Good (w r : List G) : Prop := r.prod = w.prod ∧ r.length + 4 = w.length
theorem all_results_good (hr : r ∈ plain w) : Good w r
```

前後と途中の列は空でもよく、g = k でもよい。
第一の対の後ろから第二の対を選ぶので、重なった対を同時に消すことはない。
同じ r を与える別の選択も列挙結果に残す。
例えば `[1,1,1,1,1]` では3通りの選択があり、結果は `[[1],[1],[1]]` である。
この等式も `repeated_identity_example` で証明する。

## 証拠を保持する列挙

`Certified P` は、値 x と命題 P(x) の証明を組にした結果のリストである。
Lean の `{x : A // P x}` は、そのような値と証明の型を表す。

```lean
abbrev Certified (P : A → Prop) := List {x : A // P x}
```

汎用的な操作は次の四つである。

| 操作 | 値と証拠の扱い |
|---|---|
| `values` | 証拠を取り除いて値のリストを得る |
| `keep` | 条件を判定し、成功した値に元の証拠と条件の証拠を添える |
| `mapWithProof` | 値の変換と、P(x) から変換後の性質を証明する関数を適用する |
| `bind` | 各結果の値と証拠を使って次の列挙を行い、その結果を連結する |

`cuts` は任意のリストの隣接二要素を選び、前後の列とともに返す。
`cuts_sound` と `cuts_complete` は、それぞれ実際の分解だけを返すことと、
すべての分解を返すことを証明する。`certifiedCuts` は各結果に分解の等式を添える。
これは逆元や消去の定理に依存しない、汎用的なリストの操作である。

2箇所の選択では、第一の分解を選び、等式を判定し、後ろの列から第二の分解を選ぶ。
検査用の Lean 版では、この構成を明示する。

```lean
def certified (w : List G) : Certified (Good w) :=
  bind (inverseCuts w) fun c₁ h₁ =>
    mapWithProof (inverseCuts c₁.post) (removeTwo c₁) fun c₂ h₂ => pair_sound c₁ c₂ h₁ h₂
```

`pair_sound` は二つの分解の等式を組み合わせ、両版で共有する群の等式と長さの推論を適用する。
消去結果の正しさをマッチャーの前提に入れてはいない。
提案ソースでは、同じ構成を次のように書く。

```egison
def certified (w : List G) : Certified (Good w) :=
  matchAll h : w as list G with
  | $pre ++ $g :: #(g⁻¹) :: $mid ++ $k :: #(k⁻¹) :: $post =>
    ⟨pre ++ (mid ++ post), by
      subst w
      exact two_cancel_identity pre g mid k post⟩
```

`matchAll` は、成功する各分解の値と証拠を腕に渡し、腕の結果を列挙する。
成功しなければ空のリストを返すので、対象全体を覆う `exhaustive by` は要求しない。
必要なのは、列挙がパターンの関係に対して正しく、成功する分解を漏らさないことである。
腕がリストを返す場合はリストのリストになり、連結するには `List.flatten` を明示する。
ここで検査する実行は有限リスト上の有限列挙である。

`values_certified` は、証拠を取り除いた結果が通常の列挙 `plain w` と**リストとして等しい**ことを
証明する。順序と重複も保存するので、結果が空であることによる見かけの正しさではない。
`mem_certified_iff` は、任意の成功する分解が結果に現れることも保証する。

## 帰納法の各段階で使う拡張

`plainMany n w` は、左から順に選んだ n 箇所の、互いに重ならない逆元対を消す結果を列挙する。
消去で新しく隣接した対を選ぶ処理とは異なり、各段階で元の残りの列から次の対を選ぶ。
任意の n、w、列挙結果 r について、積を保ち、長さがちょうど 2n 減ることを証明する。
`plainMany_two` により、n = 2 の列挙は上の `plain` と等しい。

```lean
def GoodMany (n : Nat) (w r : List G) : Prop :=
  r.prod = w.prod ∧ r.length + 2 * n = w.length
```

通常の証明は n について帰納し、各段階で `flatMap`・`map`・`filter` への所属を取り出して
分解の等式を復元し、残りについて帰納仮定を適用する。
証拠を保持する版では、再帰関数の結果の型を `Certified (GoodMany n w)` にする。

```lean
def certifiedMany : (n : Nat) → (w : List G) → Certified (GoodMany n w)
  | 0, w => [⟨w, rfl, by simp⟩]
  | n + 1, w =>
    bind (inverseCuts w) fun c hc =>
      mapWithProof (certifiedMany n c.post) (fun r => c.pre ++ r) fun r hr => extend_good c hc hr
```

`hr` が残りについての帰納仮定の役割を果たす。`extend_good` は、前の列を戻し、
一組の逆元を消した結果の積と長さを証明する。両版で同じ補題を使う。
型の検査によって、各段階が結果と証明を構成していることを確認する。
別に帰納法を書く代わりに、再帰する構成の中に証明を組み込む使い方である。
`values_certifiedMany` は、すべての n について通常の列挙との等式を証明する。
`MatchesMany` は n 組の分解を再帰的に表す関係であり、`mem_plainMany_iff` と
`mem_certifiedMany_iff` は任意の n について列挙の正しさと完全性を証明する。

## 比較から言えること

逆元対の例では、パターンから、二つの対が離れていて、前後と途中の列を残すことを
読み取れる。通常の列挙では `cuts`、`filter`、`flatMap` とそれらの依存関係を追って、
同じ配置を理解する。この構造の見え方を比較した上で、以下に記述量の費用を記す。

2箇所の通常の証明は、所属の証明を取り出す4行の推論で済む。
その操作を自動化した版も検査する。さらに `mem_plain_iff` を両版で共有すると、
Lean は `aesop` により1行の証明操作で示せる。
証拠を保持する版も、構成済みの結果についての主証明は汎用的な `sound` の適用で済む。
したがって、主証明だけの行数では、パターン記法固有の優位は示せない。

補助部と、通常のリストとの対応証明も含めて比較する。
空行とコメントを除き、共通部は import・namespace なども含む各ファイルのコード行を数える。
主証明と追加定義は宣言から末尾までを数え、ファイルの外枠は含めない。
通常の版は自動化した証明を選び、別証明を追加費用には含めない。

| 部分 | 通常の Lean | 提案ソース |
|---|---:|---:|
| 共通部：CertifiedList、ListCuts、TwoCancellationsCommon | 189行 | 189行 |
| `inverseCuts` と証拠を除いた値についての補題 | 0行 | 4行 |
| 2箇所：正しさの主証明／証拠を持つ構成・対応証明・主証明 | 4行 | 15行 |
| 任意の n：正しさの主証明／証拠を持つ構成・対応証明・主証明 | 8行 | 20行 |
| 上記の合計 | 201行 | 228行 |

提案版の構成を Lean で手動展開した版は、2箇所の上記部分が12行、任意の n が17行である。
通常の版の列挙定義は共通部に含め、提案版で同じ出力を表す仕様としても使う。
列挙の関係についての完全性は共通部で証明する。提案版のその関係への直接の対応を
示す `mem_certified_iff`、`mem_certifiedMany_iff` は、表の正しさの主証明に含めない。
列挙と正しさを同時に定義すること、および独立した通常の列挙との対応を証明することの
費用があるため、この完全な比較では総量は減っていない。

確認できる効果は、**列挙の結果についての証明を構成に保持し、個々の利用箇所で
所属から分解を復元する操作と、独立した帰納法の記述を省けること**である。
その効果は、証拠を持つ列挙を直接書く Lean にもある。
パターン指向言語では、選択・分解の構成と証拠の対応をパターンから生成して提供することで、
多様な形を使うたびに利用者がその構成を書かずに済むことを目指す。
生成の規則とその汎用的な証明を実装し、型の変換と証拠の引き継ぎまで検査する必要がある。

## 短縮を狙う条件

次は、短縮する操作が存在するかを調べる条件であり、最短の証明の長さについての定理ではない。

1. **選択・分解の組合せに証明上の手間がある。** 入れ子の探索、複数の対象の選択、
   前に選んだ値に依存する条件などがあり、所属・位置・等式の証拠を何度も対応付けている。
2. **選択した形から結論へ進む推論が共通している。** 各マッチ結果に同じ代数法則、
   不変条件（処理の前後で保たれる性質）、または帰納仮定を適用できる。
3. **後続の推論に必要な証拠を分解が与える。** 値だけでは足りず、分解の等式、所属、
   選択した位置の関係などを保持する。帰納法なら残りの条件と対象の減少も要る。
4. **その証拠を汎用的に組み合わせられる。** 選択、条件判定、複数の照合、結果の変換の
   規則から証明を構成し、例ごとに結論を保証する専用マッチャーを置かない。
5. **結果の構成または次の証明でも証拠を使う。** 証拠を捨てて通常の値へ戻し、
   そのたびに別の対応証明を追加すると、短縮した部分より費用が大きくなり得る。
6. **同じライブラリと自動化で比較しても、繰り返す記述が残る。** `rcases` や `aesop` で
   既にまとめられる分解は、腕を書き直すだけでは短くならない。

1–4 により、個々のマッチ結果から数学的な結論を得る共通の推論へ帰着できる。
汎用的な列挙の正しさを一度証明すれば、各利用箇所で探索への所属を分析する必要がなくなる。
5–6 は、その構成を提供する費用も含めた実際の記述量を評価するために必要である。

例えば [局所合流性](pwl-local-confluence.md) は、複数の分解を突き合わせる場面に使えるが、
その分類が共有する存在命題と選言に既にまとまっている。
Lean の `rcases` と `all_goals` でも短く扱えるため、腕をパターンにするだけでは短縮しない。
一方、証拠を保持する列挙は、その後の結果の構成や帰納的な処理まで扱える点が異なる。

- **SAT の変数消去**：検査済みの [解消規則と有限導出の正しさ](pwl-readable-proofs.md) を使い、
  すべての該当する節の組を解消する処理と、消去前後の充足可能性の同値性を証明する。
  恒真の節（すべての割当で真になる節）を除く条件もパターンで扱う。
- **複数の関係からの合成**：例えば x→y と y→z を異なる集合から選び、得た x→z の性質を
  示す。所属と共有する y の等式を、選択から結果の構成まで保持する。
- **構文木の文脈内の書換え**：部分式の選択と、その前後の文脈への再構成を繰り返し使い、
  局所的な等式を元の式の等式へ戻す操作を共通化する。

これらの拡張についての完全な比較証明は追加する必要がある。
実装では、まず検査済みの `CertifiedList` と `ListCuts` に相当する規則を基礎とし、
`matchAll` の値・証拠・結果型を確定する。
パターンからの変換器を実装して上の全コードを直接検査し、
汎用的な処理系の費用、利用者が書く局所的な証明、対応証明を分けて比較する。
全例の公理への依存は [Audit.lean](examples/lean/Audit.lean) で確認する。
