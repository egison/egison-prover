# パターンマッチ指向の証明：言語設計

## 現在の設計と例

Egison Prover は，数学的な配置を定理の言明と証明の途中で同じパターンによって
記述する証明言語を目指す．現在の比較例を [Ramsey の定理](pwl-ramsey.md) に絞り，
どの記述が省けるかを [簡潔さの評価](proof-brevity.md) で再検討する．
他の例の存在をもって簡潔さの根拠とはしない．

マッチャー（matcher）は，パターンの解釈と対象の分解方法を定める．
パターンマッチは，対象が条件を満たすか調べ，成功時に選んだ値を変数へ束縛する．
`$x` は束縛，`#e` は式 `e` との等式，`_` は束縛しない部分である．
先行する束縛への参照を持つパターンを非線形パターンと呼ぶ．

Ramsey の三角形は次のように表す．`Fin 6` は0から5の頂点の型，
`Sym2` は順序のない対，`Color` は赤と青の型である．

```text
edge matches ($x, $y) → $c :: (#y, $z) → #c :: (#z, #x) → #c :: _
  as multiset (Sym2 (Fin 6) → Color)
```

辺と色の観察を組み合わせ，共通の端点と色を同じ式で指定する．
星のパターンを補題の結論と主証明の分岐で共有することで，存在する配置と
証明で使う配置を対応付ける．完全な上界・下界と定義は [examples/](examples/README.md) にある．

## 関係と証拠

各パターン P について，束縛値の型 B と，対象 e と束縛 b の関係 R(e,b) を定める．
`e matches P as M` は `∃ b : B, R(e,b)` という存在命題である．
選んだ値を計算用のデータとして返す場合は，値と関係の証明を持つ依存対
（後の成分の型が前の値に依存する組）などを別途用いる．
命題の証明から任意のデータへ場合分けする規則は置かない．
型の型である宇宙にはレベルを設け，`Type : Type` は仮定しない．

`match` の各分岐は束縛値と関係の証明を受け取る．
`exhaustive by` は少なくとも一つの分岐が成立することを証明する．
複数の分岐が成立してもよく，各分岐は前の分岐の不成立に依存しない．
データを返す場合には，命題としての存在だけでなく，分岐とその値を選べる証拠が必要である．

`P & Q` は同じ対象への二つの関係，`P | Q` は選択肢ごとの束縛と関係を表す．
バリューパターンは先行する束縛と外側の文脈だけを参照する．
一般の否定パターン `!P` は成立する束縛の不在を表し，内部の変数を外へ渡さない．
探索の失敗から否定を得るには，探索の完全性が必要である．

分岐では条件を暗黙に保持し，目標に `exact ⟨values⟩` で値を与えると，
その条件と証明済みの補題から必要な証明項を構成するものとする．
条件の取得・合成・証明構成の具体的な機構は今後設計する．
[共通方針](implicit-conditions.md) と，手動で証拠を展開した Lean の版を区別する．

## Ramsey の観察

多重集合は，順序を区別せず，出現の重複を保持する．
有限関数 f の観察には各入力 a について一つの `(a,f a)` を用いる．
`::` は一つの出現を選んで取り除くため，異なる観察の入力キーは相異なる．
残りは入出力の組の多重集合であり，全関数ではない．
内側のパターンマッチは元の `edge` を改めて観察する．

辺のパターンは端点が相異なることを要求し，順序のない対のどちらの向きも許す．
固定頂点の異なる三辺を選ぶと，他方の端点の相異性も得られる．
同じ色は `#c` で表す．数え上げと内部辺の二色の場合分けは網羅性の補題で証明する．
これらの数学的な証明はパターンの表示だけからは得られない．
